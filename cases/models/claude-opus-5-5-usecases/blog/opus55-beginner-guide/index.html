适合谁：想自己用 Claude Opus 5.5 做东西的新手。会用聊天类 AI 就够，不会编程也没关系。

前提：一个能用 Opus 5.5 的 Claude 付费账号。

两个入口，先分清：claude.ai 网页 / App 与 Claude Code

claude.ai 网页 / App

  • 直接聊天，不用安装任何东西。
  • 做出来的单页网页可以直接在对话里预览。
  • 第 1、2 步用它就够。

Claude Code

  • 能读写你电脑上的文件、运行命令，适合长任务和做完整项目。
  • 不会用命令行，就用 Claude 桌面应用里的 Claude Code。下文两位“不写代码”的作者用的都是桌面版。
  • 安装方法见官方页面 code.claude.com（新窗口）↗ 未测试。
在大陆访问 & 关于数字X、YouTube、Reddit 需翻墙

在中国大陆访问：X、YouTube、Reddit 需要翻墙；B站、GitHub、Zenn、note、Qiita 一般能直接打开，日文文章用浏览器整页翻译就能读。下文推荐资料表里每份资料都标了能否直连；避坑一节出处里的 X、Reddit 链接需翻墙，官方帮助中心可能也需要。

关于数字：文中的时间、费用、额度都是原作者自述，多数只跑了一两次。帖子里的美元数多是按 API 价格折算，订阅用户实际扣的是额度，不是账单。

01第 1 步 / 共 5 步 · 只需 claude.ai把任务一次交代清楚

官方上手手册“第一次会话先试三件事”的第一条是：把整件事一次交出去，并写清楚做完长什么样、什么时候停下来问你。Opus 5.5 能连续工作很久，交代得越完整，越不容易跑偏。

要做的：

  • 用途和对象：一次交出整个任务，写清做什么、给谁用。
  • 完成标准：写清“做完”长什么样，比如必须做到的 3 件事。
  • 何时停下问我：遇到需要你拍板的事、删数据这类不可逆操作之前，先停下来。
  • 不要什么：具体列出来，做网页时写出“不要哪些设计套路”，不要只说“别太普通”。
  • 交付前自查：比如“检查每个按钮能不能用”，或“找出数字、日期、名字互相矛盾的地方，引用原文并写明位置”。
  • 另外，资料直接给原件：图表、截图直接上传，不要手抄数字；要完整的表格或文件，不要只要大纲。

要删的：“请仔细思考”“think carefully”这类话。官方手册说 Opus 5.5 每次回复前本来就会思考，删掉这句后回复开始得更快，质量没有明显下降。同样别一律开最高档：一位作者称，只改了思考档位这一项设置（点送出键旁的模型名就能看到），同一份工作就从约 102 秒降到约 20 秒，答案一样。

02第 2 步 / 共 5 步 · 只需 claude.ai做出第一个成品，并学会改稿

最容易成功的第一个作品，是用一条写清楚的提示词，在 claude.ai 里做一个能在浏览器打开的单页：习惯打卡、月度预算、节日贺卡都行。第一版很少一次就满意，所以这一步真正要学的是怎么提修改意见。

改稿的核心习惯：

  1. 做完先自己打开看（claude.ai 里在对话中直接预览就行）。没给它截图工具时，它看不到自己做出的画面，只有你看得到。
  2. 把截图或报错贴回去，让它按“影响大小”排序，一次最多改 3 处。一位日本作者用 12 张截图这样提要求，称第一轮就把 260 条报错降到 0。
  3. 遇到黑屏或报错，先别急着调高档位。同一位作者发现，长任务先降一档做出能跑的版本，再把复杂效果一项项加回去，更容易成功。

不满意时，按 6 项写清楚问题（来自一位 B站 UP 主的反馈模板）：

写清楚说明UP 主的例子
位置或时间点问题出在哪个区域、哪一秒海岸浪峰
目前看到什么客观描述现状，最好附截图泡沫在撞击前从浪底出现
为什么不对违反了什么常识、需求或顺序违反破浪顺序
想要的效果改成什么样才算对浪峰先落、再产生泡沫与喷雾
改动范围只改哪里，哪些地方不要动只改破浪段
怎么验证改完后你会怎么检查从三个不同视角看短样片，并观察性能

03第 3 步 / 共 5 步 · 多数要用 Claude Code用 Claude Code 前，弄懂档位和额度

只用 claude.ai？思考档位保持默认即可，这一步可以先跳过；只需记住：换到无关的任务就开一个新对话，同样省额度。 跳到第 4 步 →

Claude Code 里的 effort（投入档位）决定它想多久、自查和核实做得多细。一位作者打了个比方：同一个人，你说“大概看看”还是“全部核实”，能力一样，只是核实程度不同。Opus 5.5 的默认是 medium，比之前的模型低一档，大部分工作不用改。

档位适合提示
low头脑风暴、画草图、小改动适合快速出第一版
medium大部分日常工作Opus 5.5 的默认值
high需要验证、边界情况多的活卡住时先升到这一档
xhighhigh 还不够、需要想得更深的活比 high 更慢、更耗额度
max完全放手让它自己攻克难题最耗时间和额度；不能存成默认值
  • 怎么切：对话中输入 /effort；桌面版快捷键 Cmd/Ctrl+Shift+E 切档位，Cmd/Ctrl+Shift+I 切模型。
  • 推荐流程：先让它反过来问你、把需求补全 → 用 low 做出第一版 → 自己看方向对不对 → 最后切到 high 做验证。
  • 升级路线：默认 medium，卡住调 high；开到 xhigh 仍在同一个问题上连卡两次，再考虑换更贵的 Fable 5.1，解决完再切回 Opus 5.5。

额度为什么会突然用光：每跑一轮，都要把整段对话重新发一遍，所以开销取决于任务跑了多少轮。省额度的做法：

  • 换到无关的任务就用 /clear（清空当前对话，从头开始），不要在一个对话里越聊越长。
  • 想保留前情就用 /compact（把前面的对话压缩成摘要再接着聊），而且要在缓存失效前做。缓存让重复发送的旧对话更省额度，订阅用户的缓存保留 1 小时。
  • 中途切换模型、接入或断开 MCP（让 AI 直接读外部数据的插口），都会让缓存重写，额外耗额度。
  • 不是每件事都要用 Opus：一位作者让 Sonnet 5.5 和 Opus 5.5 各做 7 类工作，修 bug、小工具、写开头、点评图片两者打平；算钱和查事实 Opus 更准。他的分工是日常活先用 Sonnet，算钱查事实用 Opus。

真实教训

没有必要别开 max；额度掉得快时，先看应用里的用量明细。

一位不会写代码的小老板把 effort 调成 max，“没有特别理由”。之后 /code-review 一次并行起了 10 个子代理（它分派出去同时干活的帮手，每个都要消耗额度），连续两天分别在 8 分钟和 4 分钟内用光 Pro 套餐的 5 小时额度。作者也说明，当天模型、effort 和应用版本是一起变的，没能分清是哪个引起的。

方向 1 / 4视频动效

先弄懂原理：Opus 5.5 不直接生成视频。它写代码一帧帧画出画面，再用浏览器截帧、用 FFmpeg 合成，所以擅长动态图形和讲解动画，不擅长写实镜头。

  • 要准备什么：Claude Code（effort 调到 high 或 xhigh），电脑上装好 Node.js、Chrome、FFmpeg。先不装也能试：只用 claude.ai 加录屏工具，见下表第一份资料的第 07 条。
  • 写法经验：先分镜后代码；列一份“禁用清单”；让它自己抽帧检查、返工。
  • 先改输入，再考虑调高档位：一位作者用同一提示词只改 effort 做了四版动画，盲看分不出高低；真正让画面变样的，是把抽象的旁白换成第一人称、有转折的一段话。他的说法是“旁白里的名词，就是模型要画的东西”。
  • 对成本有现实预期：一份中文合集的 README 称，一句话短片几美元，几分钟的 MV 单次会话可能到约 200 美元。所谓“一次成型”，很多其实跑了两轮以上。

方向 2 / 4网页与小游戏

一位“开发方面完全外行”的作者，用 Claude 桌面版里的 Claude Code，在一天里把做到一半的塔防游戏推进到 v1.0 并上线：到 v1.0 一共发了 25 条消息，其中只有 8 条是修改要求。他和 AI 一起复盘出的下指令方法：

方向 3 / 4Claude Code 工作流

核心是学会“把活交到底”：写清输入在哪、输出成什么文件、完成标准是什么、做不到就直说。

  • 输入和输出分开放（如 input/ 与 output/），不许改原文件。
  • 要求它在 report.md 里写清怎么做的、哪些没做到或没把握。
  • 用一份 TASKS.md 记录进度；一个提示框架是 Goal / Why / Context / Done when / Boundaries。
  • 子代理的权限要真的锁住：一位作者自查发现，33 个子代理定义里只有 4 个限制了工具权限。规则写在文字里，不等于权限生效。

为什么会被换模型或拦截：官方帮助中心说明，安全分类器会把网络攻击类请求回退到 Opus 4.8，把生物两用类和前沿大模型开发类回退到 Opus 5，并直接拦截“逐字输出完整思考过程”这类请求；大多数请求不会触发。分类器不只看你打的字，也看记忆、连接器、搜索结果和文件。

不想被自动换模型：在 设置 › Capabilities（Claude Code 里是 Config › MODEL & OUTPUT）关闭 “Switch models when a message is flagged”。

一定要记住

凡是涉及磁盘、备份、删除的操作，都不要开自动执行或跳过确认；模型提出破坏性操作时先停下来核实，别用时间压力催它，动手前先备份。

A附录 A · 路线之外怎么判断一条案例值不值得信

挑选这份清单时用的就是下面几条，你自己在图谱里翻时也能用：

  • 跑了几次？只跑一次的结论很容易翻。有作者把同一道题重跑一次，原本会主动联网的模型也不查了。
  • “一次成型”是真的吗？很多“一次成型”其实跑了两轮以上。
  • 档位越高越好吗？盲测里 max 比 medium 多花约 7 倍时间，成片却分不出来。
  • 钱是怎么算的？美元数多按 API 价格折算，订阅用户扣的是额度。
  • 有没有能打开的成品、完整提示词和失败记录？三样都有的，比只放一段炫酷视频的可信。
  • 有没有推广？内容可以用，但要知道作者的立场。
