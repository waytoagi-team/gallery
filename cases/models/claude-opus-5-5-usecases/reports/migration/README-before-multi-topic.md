# Opus 5.5 Use Cases

A structured, local collection of public Claude Opus 5.5 use cases, plus a single-file HTML browser.

## Output
- `index.html`: open it directly in a browser. It is self-contained (data embedded) and has search (with highlighting and filter suggestions), category/source/evidence-type filters with a result line under each filter group, sorting (curated mix by default, trending, likes, saves, date), load-more paging, and a zh/en toggle. Filters, search, sort and language are kept in the URL (`?src=&cat=&ev=&q=&sort=&lang=`), so views can be shared.
  - The build (`render_page` in `scripts/build_html.py`) pre-fills the zh first screen and embeds a small BOOT summary (counts, a source×category×evidence count cube, most-liked list) before the large case payload, so the first screen renders with exact numbers before the data is parsed. Poster URLs in the page (not in `data/`) request card-sized WebP thumbnails from twimg/hdslb.
  - `renderStatic()` in `scripts/template.html` and `hero_blocks()` in `scripts/build_html.py` produce the same hero markup; change them together, then check that each pre-filled block (`#tagline`, `#heroCta`, `#infoCard`, `#stats`) equals its innerHTML after load.
- `assets/og-image.png`: 1200×630 link-preview card for X, Telegram, Discord, Slack, Feishu and other og:image readers. `scripts/og_image.html` is the template; its `{{COUNT}}`, `{{LIMITS}}`, `{{CATEGORIES}}`, `{{SOURCES}}` and `{{AS_OF}}` are filled from `data/all_cases.json` by `scripts/render_og.py` (needs Playwright + Chromium). The sample case cards on it are real records (`uc-0231`, `hn-049`, `lists-010`, `github-249`, `reddit-052`). The page links the image with a content hash (`?v=`) so platforms re-fetch it after a refresh, and fills og/twitter alt text from the same numbers. WeChat ignores og tags (custom WeChat share cards need the Official Account JS-SDK); it shows the page title.

- `blog/opus55-beginner-guide/`: Chinese beginner guide (5-step learning path distilled from 30 verified cases; same content as the WaytoAGI Feishu doc). Static article: edit `index.html` directly; figures are WebP in `img/` with `-1200` variants for `srcset`; the share card `img/og.png` is rendered from `scripts/og_guide.html`. The atlas links to it from the header and hero (`{{GUIDE_URL}}` in `scripts/template.html`).

- `assets/waytoagi-logo-{light,dark}.svg`: official WaytoAGI logos, inlined into `index.html` at build time. The page follows the WaytoAGI brand design system.

Fields: `id, source(x/github/hn/web/reddit/video), platform, category, evidenceType(演示/评测/集成/教程/限制), title, title_en, summary, summary_en, author, sourceUrl, date, likes, bookmarks, stars, githubKind, reactions, comments, metricsSourceUrl, metricsCheckedAt, mediaKind, poster, posterEvidence`

GitHub metrics belong to the linked object. `githubKind` distinguishes repositories, PRs, issues, files and Gists. Only repository entries have `stars`; PRs and issues have their own body `reactions.total_count` and discussion `comments` (excluding inline review comments). Reactions include all types, not just approval. Comments are displayed, never scored. File/Gist entries have no independently collected popularity metric. `metricsSourceUrl` identifies the exact API object used; missing counts stay unknown rather than becoming zero.

Trending uses a midrank percentile within each comparable source/metric group, with separate GitHub repository, PR and issue groups and separate video views/likes groups. Equal counts tie, zero scores zero, missing data is unranked, and a positive singleton scores 0.5. The curated mix uses these scores within its source queues. Popularity does not measure quality. The [October 3 metric correction](UPDATE-2026-10-03-github-metrics.md) removes incorrectly inherited stars from 68 entries and records the full audit.

The October 1 poster review checked all 1,420 cases without an image and added 533: X 178, Reddit 143, GitHub 123, web 74 and Hacker News 15. Image coverage after that review was 4,294 / 5,181 (82.9%); 887 cases remained without a verified suitable image. Images come from original attachments, explicitly quoted or linked works, project screenshots and case-specific article figures/covers. Generic platform cards, unrelated photos, badges and blank video frames were excluded. External image links retain the original owners' rights; raw images and article bodies are not mirrored.

`poster_enrichments.json` survives offline rebuilds. Each patch must match both the case ID and source identity (including the title for distinct experiments on a shared editorial URL); existing upstream posters take precedence. `posterEvidence` records the source page, relationship, image URL actually checked, dimensions, check time and SHA-256. Both JSON and CSV include the poster and provenance; the page embeds only its display fields. [Review decisions](data/refresh_history/2026-10-01-poster-review.json) cover every initially missing case and distinguish missing media, uncertain matches, unavailable sources and failed image checks.

## Rebuild
```bash
python3 scripts/fetch_base.py       # fetch the base case list -> data/_raw_base.json
python3 scripts/normalize_base.py   # raw -> data/base_cases.json
python3 scripts/collect_sources.py # fetch discovery snapshots; review before adding extras
python3 scripts/refresh_metrics.py # refresh existing X/GitHub metrics; keep previous values on failures
python3 scripts/build_html.py       # merge extras -> data/all_cases.json / .csv + index.html
python3 scripts/render_og.py        # re-render the share card with the new numbers, then build_html.py again (?v= hash)
```

Repository collection: [waytoagi-team/gallery](https://github.com/waytoagi-team/gallery/tree/main/cases/models/claude-opus-5-5-usecases).

`refresh_metrics.py --output-dir data/_refresh/YYYY-MM-DD` saves fetch receipts and a summary. A nonzero exit indicates partial failure; successful metrics are still saved. It does not change the published refresh report or rebuild the page. Archive the previous report and update the report's scope and validation before rebuilding.

GitHub API requests in both collectors use the active `gh` login (`gh auth status`; if needed, `gh auth login --hostname github.com`). The scripts delegate authenticated GET requests to `gh api`; credentials are not copied into project files or receipts. API failures retain their status and public rate-limit headers. Raw GitHub files and other platforms use their existing public transport. To refresh GitHub object metrics alone, run `python3 scripts/refresh_metrics.py --only github --output-dir data/_refresh/github-authenticated`; add `--github-kind repository` or `--github-kind thread` to restrict requests. This preserves X metrics and their refresh timestamp. Failed PR/issue requests retain previous metrics only when their API provenance matches; incorrect parent stars are removed even on failure. Both refresh and offline build enforce object attribution. Metric collection defaults to two concurrent requests; adjust with `--workers`.

See [the September 27 update log](UPDATE-2026-09-27.md) for source recommendations and coverage. `collect_sources.py --since YYYY-MM-DD` writes ignored snapshots and a status manifest under `data/_refresh/latest/`; it does not publish unreviewed search hits. A nonzero exit means at least one source failed; successful snapshots remain available.

Deduplication uses original post/video/repository identities; editorial pages may retain multiple distinct cases. Newly reviewed extras include `checkedAt`, `discoveredVia`, `evidenceUrl` and `evidenceBasis`. Metric-only refreshes use `metricsCheckedAt`. `meta.asOf` is the newest known case date; `meta.refreshedAt` is the latest update time, `meta.refreshScope` states its scope and `meta.lastFullRefreshAt` retains the prior multi-source refresh time.

The Lemo-Opuscar, Blender AI Arena and Qiita session-log cases include six direct resource links to prompts, guides, methodology and the analysis script. The optional `resources` field contains `{label, label_en, url}` entries, appears on case cards in both languages, and is preserved in JSON and as a JSON-encoded CSV cell. Search for the source name to find each case. These enrich existing records. The September 28 GoSail pass adds 203 cases, enriches 629 existing cases, and preserves 248 prompt evidence links across 244 cases.

Validation: `python3 -m unittest discover -s scripts -p 'test_*.py'` (32 tests covering source identity, GitHub API metrics, enrichment and rendering) and `node --test scripts/test_ranking.cjs` (3 ranking tests).

See [the complete GoSail update](UPDATE-2026-09-28.md) for all-source decisions and evidence limits. To retrieve the pinned snapshot again:

```bash
python3 scripts/collect_gosail.py --ref ffb3c5a22d27c0d9a5328ffbfb2df33e0887103c --output-dir data/_refresh/gosail
python3 scripts/import_gosail.py --cache data/_refresh/gosail
python3 scripts/build_html.py
```

`import_gosail.py` requires a decision for every source entry and checks the snapshot and post receipt hashes. A new upstream revision needs a new review. Reretrieval changes observed metrics and timestamps; the committed extras and overlay rebuild the published snapshot offline. `promptEvidence.kindReported` retains the curator's full/brief label; `completenessVerified` remains false. No prompt bodies or videos are mirrored.
