# Claude Opus 5.5 真实案例使用图谱：视觉与交互审查报告

**范围**：线上页面 https://www.waytoagi.com/usecase-atlas/opus5-5/ ，改动目标是 `scripts/template.html`（下文 L 行号均指这个文件）。共 8 个维度的审查结果加 1 轮补漏，所有结论都经过二次复核，重复项已合并。

**证据路径**：文中的 `shots/…`、`probes/…` 是审查时的临时截图与探针脚本，未随仓库保存；结论中的数字均已在审查和复核中实测。

**结论**：品牌视觉执行得很扎实。主要问题集中在"找到并打开一个案例"这条主路径上：
- 卡片本身点不开；
- 大陆网络下缩略图会塌陷；
- 在列表深处改排序或搜索后，列表会"消失"，也不再继续加载；
- 平板宽度下页头断行；
- 首屏在数据加载完之前是空骨架。

以上 5 项列为 P0，基本都是 S 级改动。

## P0：必须修（功能失效或误导，手机和"找案例"主任务受影响最大）

### 1. 卡片看起来能点，其实只有一个 16px 高、被截断的作者名能点
- **问题**：
  - 标题和缩略图都不是链接，每张卡通往原帖的唯一入口是 `.foot a`，高 16px。
  - 1440 宽时首批 48 张里有 38 张作者名被截断：`@higgsfield_ai ↗` 只显示 30px/115px，渲染成 `@hi…`。1024 宽时 43/48 张被截断，最窄只剩 15px（`shots/w1440-deep-grid.png`、`w1440-cases-images-after-4s.png`）。
  - 390 宽手机上，链接面积只占整张卡的 1.1%。
  - 与此同时 `.card:hover` 会把边框变成 ink 色，暗示整张卡可点。
  - 原因是 `.nums` 设了 nowrap，最宽 209px，而 `.foot` 只有 249px，把作者名挤没了。
- **建议**：
  - 标题做成主链接：`<h3><a class="card-link" href="${esc(c.sourceUrl)}" target="_blank" rel="noopener">…</a></h3>`，并加 `.card:hover h3{color:var(--blue)} .card:focus-within{border-color:var(--ink)}`。
  - 整卡可点用事件委托，**不要用 `::after` 铺满整卡**。实测铺满后摘要无法拖选复制（可选中字符从 82 变成 0），而中文读者经常复制摘要转发：
    ```js
    $('#grid').addEventListener('click',e=>{if(e.target.closest('a')||String(getSelection()))return;
      const c=e.target.closest('.card'); if(c) c.querySelector('h3 a').click();});
    ```
    同时加 `.card{cursor:pointer}`。
  - 作者名改成纯文本，或加 `tabindex="-1" aria-hidden="true"`，避免每张卡出现两个指向同一 URL 的 Tab 停靠点。
  - 页脚改为 `.foot{flex-wrap:wrap;row-gap:4px} .foot a{flex:1 0 auto}`。实测 1440 和 1024 下截断、溢出都是 0，页脚只增高约 27px。
  - **不要**用 `.foot a{min-width:45%}`：实测会让 `.nums` 溢出卡片右边 57–65px。
- **位置**：L139-140、L155、L160-163、L452-457
- **工作量**：S

### 2. 近 90% 的缩略图在大陆访问不到；失败时整个 thumb 被删，卡片跳动
- **问题**：
  - 3,679 张海报中，3,262 张（88.7%）托管在 `pbs.twimg.com`、`i.ytimg.com`，默认排序前 96 张全是 twimg。
  - 请求挂起时，卡片只显示一块无品牌的灰框 `#f6f4f5`（`probes/mobile-w390-twimg-hang.png`）。
  - 超时后，L449 的 `onerror="this.parentNode.remove()"` 会把整个 thumb 连同 `▶ VIDEO` 一起删掉。390 宽时标题从 410px 跳到 218px，CLS 0.31–0.47；1440 宽 CLS 0.22–0.23。
  - 现有的品牌来源色块 `.thumb.src` 在失败时完全没派上用场。
- **建议**（零 JS 方案，实测两种宽度都 0 位移）：始终在图片下面画来源色块，出错时只删 `<img>`。
  ```html
  <div class="thumb" data-s="${esc(c.source)}"><span class="ph" aria-hidden="true">${esc(c.platform)}</span>
    <img … onload="this.classList.add('ok')" onerror="this.remove()">…</div>
  ```
  ```css
  .thumb{background:var(--lilac) linear-gradient(rgba(36,30,30,.07) 1px,transparent 1px) 0 0/12px 12px,
         linear-gradient(90deg,rgba(36,30,30,.07) 1px,transparent 1px) 0 0/12px 12px}
  .thumb .ph{position:absolute;left:20px;top:14px;font:800 20px var(--font-display);text-transform:uppercase}
  .thumb img{position:relative;opacity:0;transition:opacity .25s} .thumb img.ok{opacity:1}
  ```
  - 挂起、被墙、失败三种状态看起来一样，16:9 框也不会变。
  - **不要**加"8 秒超时强制失败"：懒加载时还没发请求的图也会被判失败，实测误伤 36/48 张。
  - **不要**在出错时换成 `.thumb.src`：它的高度是 64px，照样会位移。
  - 长期方案：在 `build_html.py` 里把海报转存到 waytoagi.com 同一个 EdgeOne CDN，转成 640×360 WebP，每张约 15–30 KB，每次部署约 75–110 MB。前提是构建机能访问 twimg，并且确认有转存权限。
  - 另外，首批 48 条原帖链接全部指向 x.com，大陆微信里打不开，可以考虑加一个"复制链接"的备用操作。
- **位置**：L141-150、L448-450；`build_html.py`
- **工作量**：S（色块兜底）/ L（自托管）

### 3. 在列表深处改排序、搜索或清除筛选后，页面停在页脚且不再加载
- **问题**：`render()`（L465-471）把网格重置为 48 张，但 `scrollY` 保持不变，带来三个后果：
  - (a) 1440 宽时从 scrollY 29,846 改成"时间从新到旧"，页面落到 12,499，第一张可见的是新列表第 92 张，屏幕上主要是紫色 CTA 和页脚。390 宽搜 `ffx` 显示"1 个案例"，但这张卡藏在吸顶栏下面（`probes/filtverify-w390-ffx-deep.png`），用户会以为没结果。
  - (b) 此时 `#sentinel` 已经处在 800px rootMargin 以内，IntersectionObserver 不会再触发，列表永久停在 96/5,053 张，继续滚动也不加载（`probes/critic-io-stall-w1440-after-wheel.png`），而 `#count` 仍然显示"5053 个案例"。
  - (c) 没有筛选时，无限加载会一直把 `.join` 和页脚往下推：连续 60 次滚轮加载了 2,352 张卡，`.join` 一次都没进入视口。投稿表单、数据下载和免责声明实际上够不着。
- **建议**：
  1. `render()` 结尾把视口回到结果区顶部。必须测量**非 sticky** 元素：`.controls` 吸顶时 `rect.top+scrollY` 恒等于 `scrollY`，原先的方案因此无效。
     ```js
     const top=$('#cases .rule').getBoundingClientRect().bottom+scrollY;
     if(scrollY>top) scrollTo({top,behavior:'instant'});
     ```
     实测第一张卡落在 y=142（1440）和 y=189（390），`#q` 保持焦点。01 和 02 区里的点击因为 `scrollY<top`，不会触发这次回位。
  2. 每次 render 后重新观察 sentinel：`io.unobserve(sent); io.observe(sent)`，重新 observe 一定会立即投递一次初始回调。
  3. 自动加载 2 批（96 张）后，改成显式按钮：`<button class="more">加载更多 · 已显示 96 / 5,053</button>`。样式用 1px ink 边框、方角、mono 计数，hover 时 lime 底。按钮放在 `#sentinel` 的位置，全部加载完后隐藏。点击后把焦点移到新插入第一张卡的标题链接。进度只写在按钮文字里，避免和 `#count` 的播报重复。
- **位置**：L304、L459-471、L482-484
- **工作量**：S

### 4. 761–1049px（iPad 竖屏、手机横屏）页头断行或溢出
- **问题**：
  - `.brand .cn`（通往AGI之路）只在 ≤760 和 1050–1399 隐藏，逻辑正好反了：它偏偏在最窄的 761–1049 显示，品牌块宽 376px。
  - zh 下 768、820、834 宽时，导航每行只放一个汉字，页头高 124px，"提交案例"按钮 74×123（`shots/w768-top.png`）。
  - en 下导航溢出，文档宽 869px，CTA 被裁掉（`probes/mobile-w768-en-hdr.png`），手机模拟时整页被缩到约 88%。
  - 反过来，1050–1399 其实放得下（1050 宽显示中文名后还余 155px），1366 笔记本用户却看不到中文品牌名。
- **建议**：
  ```css
  @media (max-width:1049px){.brand .cn{display:none}}
  @media (min-width:761px) and (max-width:1049px){.nav{gap:18px}.brand svg{width:180px}}
  .nav a,.nav button.lang,.nav .cta{white-space:nowrap}
  ```
  同时删除 L188 的 `.brand .cn{display:none}`。实测 761–1049 页头都是 89px，`docW==innerWidth`，zh 和 en 都没有溢出，≤760 的下拉菜单不受影响。
- **位置**：L32-41、L188、L194
- **工作量**：S

### 5. 首屏在 4 MB 数据解析完之前是空骨架，内容弹出时 CLS 0.44–0.63
- **问题**：
  - 所有可见文字（chip、tagline、信息卡、统计、来源栏、章节标题）都靠 JS 在 L328 的 3.98 MB 内联 JSON 解析完以后才填进去。
  - 慢速 4G + 4x CPU 下，FCP 0.49s 时屏幕上只有"Claude Opus 5.5"、两个只剩四角圆点的空 chip、一张空的 lilac 卡片、一条空的 route-result、一个孤零零的"01"（`probes/perf_load_mobile-slow4g-cpu4_6.png`）。LCP 为 7.1s。
  - 内容一次性弹出，CLS 0.438（1440）/ 0.628（390），远超 0.1 的"良好"线。
  - 线上是 no-store（见 #16），所以每次回访都会再看一遍这个骨架。
- **建议**：
  - `build_html.py` 预渲染默认的 zh 状态：把中文文案写进所有 `data-i18n` 节点，tagline、`#infoCard`、`#stats`、`#route`、`#routeResult` 直接输出成静态 HTML（Python 可以从 meta 和计数算出来）。实测 CLS 为 0/0，LCP 约等于 FCP（588–728ms）。
  - 卡片不需要预渲染，网格起点在 y=2481（1440）和 3667（390）。
  - 对 localStorage 里 `lang=en` 的访客：在 `<head>` 放两行内联脚本给 html 加 `en` class，hydrate 前用 `html.en [data-i18n]{visibility:hidden}` 隐藏中文。
  - 兜底规则：`.chip-t:empty,.route-result:empty{display:none}`。
  - min-height 占位几乎没用（CLS 0.628→0.597）。只把 app script 移到数据块前面也没用，因为 L331 同步读取 `#data`。
- **位置**：L247-263、L269/279/287、L328-331、L409-423、L486；`build_html.py`
- **工作量**：M

## P1：高价值

### 6. 点了筛选，视口里看不到结果变化；读屏用户什么也听不到
- **问题**：
  - 三处筛选（来源栏、01 分类柱、02 证据区）距离结果区 1.4k–2.4k px，点击后页面不滚动。
  - 1440×900 下，来源点击后的 `#routeResult` 在 y=907，刚好在折线下面。
  - 点分类柱下半部分（第 10 条起）或整个证据区后，视口里唯一的变化是 lime 底色（`probes/visual-polish-m390-after-bar-tap.png`：点"音乐与声音"后计数变成 94，但它在约 1,950px 以下）。
  - 状态句只描述来源：只选了 3D + 评测时显示"当前：全部来源 · 135 条"；Reddit + 限制结果为 0 时，也不说是哪个条件导致的。
  - 全页没有任何 `aria-live` 或 `role=status`。
- **建议**：
  1. 复用 `.route-result` 的样式，在 `#bars` 和 `#evGrid` 后面各渲染一行"当前：Reddit · 游戏开发 · 限制 → 12 条 · 查看案例 ↓ · 清除"。证据区用深色版，文字用 lime。每个条件用带 ✕ 的 `.pill` 显示，免得句子在 390 宽下太长。
  2. 状态句由所有条件拼成：`[st.src&&srcName(st.src), st.cat&&CATS[st.cat][st.lang], st.ev&&evName(st.ev), st.q&&`“${st.q}”`].filter(Boolean)`。
  3. 来源点击后执行 `$('#routeResult').scrollIntoView({block:'nearest'})`（1440 下只滚约 140px），不要强行跳到 `#cases`。
  4. 加一个专用的 `<p class="sr" role="status">`，内容和状态句相同，例如"已筛选：Reddit · 游戏开发，64 个案例"，搜索无结果时写入空状态文案。
  5. "点赞最多"列表不随筛选变化，标题改为"全站点赞最多"。
  - 如果改做底部浮动条：只在"有筛选且 `#cases` 不在视口内"时显示，不要定时消失；而且要在 `render()` 里根据 `casesVisible` 标志重新计算 `hidden`。只在 IO 回调里设置的话，点击后浮动条永远不会出现。
- **位置**：L263、L271、L280、L353/366、L421、L429-430、L473-481
- **工作量**：S–M

### 7. 键盘切换筛选后焦点掉到 `<body>`；吸顶栏会盖住聚焦的元素
- **问题**：
  - L427/434/436/442 每次都用 innerHTML 重建按钮。按 Enter 或 Space 后 `activeElement` 变成 BODY，下一次 Tab 跳回这一组的第一项；要重新选第 12 条分类，得多按 11 次 Tab。
  - 反向 Tab 时，sticky `.controls` 会完全遮住聚焦的卡片链接：1440 宽 11/30 次，390 宽 14/30 次（`probes/a11yv-shifttab-390.png`）。有 pill 时吸顶栏更高，情况更糟。
- **建议**：
  ```js
  // click handler 开头，改 st 之前
  const had=document.activeElement===t, attr=['src','cat','ev'].find(k=>t.dataset[k]!==undefined), prevSrc=st.src;
  // …原有状态修改…
  render();
  if(had){ let b=attr&&document.querySelector(`button[data-${attr}="${t.dataset[attr]}"]`);
    if(!b&&t.closest('#routeResult')) b=document.querySelector(`button[data-src="${prevSrc}"]`);
    (b||$('#active .pill')||$('#q')).focus({preventScroll:true}); }
  ```
  - 不要改成"节点常驻，用 appendChild 重排"：Chromium 里移动已聚焦的节点会让它失焦。
  - 吸顶遮挡的处理：
    ```js
    new ResizeObserver(([e])=>document.documentElement.style.setProperty('--ctl-h',e.target.offsetHeight+'px')).observe($('.controls'));
    ```
    ```css
    #grid a,#grid button{scroll-margin-top:calc(var(--ctl-h,80px) + 16px)}
    @media (max-height:500px){.controls{position:static}}
    ```
  - 用 scroll-margin，不要用 html 的 scroll-padding，否则 `#overview`、`#evidence` 的锚点会被偏移。
- **位置**：L129、L425-443、L473-481
- **工作量**：S

### 8. 手机搜索栏：iOS 聚焦时自动放大，吸顶栏占掉 15–27% 屏高
- **问题**：
  - ≤760 时 `body{font-size:14px}`，而 input 和 select 用的是 `font:inherit`，所以 `#q`、`#sort` 实际是 14px。iOS Safari 和微信 iOS 在聚焦时会自动放大（依据 WebKit 的已知行为推断，没有在真机上观测）。
  - 吸顶栏在 390 和 360 宽时高 124px；有 3 个 pill 时 163px；pill 较长或 en 模式下达到 197px（360×740 的 26.6%）。键盘弹起后只剩约 340px，而一张卡平均 401px。
  - 吸顶状态下没有阴影，只有一条 1px `#DDD7DB` 线（1.42:1）。
  - 搜索框 49px，select 41px，两者不等高。
- **建议**：
  ```css
  @media (max-width:760px){
    .search,select{font-size:16px}
    .controls{padding:8px 0} .controls .row{flex-wrap:nowrap;gap:6px}
    .search{flex:1 1 auto;padding:9px 12px} select{flex:none;width:auto}
    .active{flex-wrap:nowrap;overflow-x:auto;scrollbar-width:none;margin-top:8px} .pill{flex:none}
  }
  #sort{align-self:stretch}   /* 实测和搜索框都是 49px */
  ```
  - 手机上用短排序文案：默认 / 最多赞 / 最多收藏 / 最新 / 最早（Default / Likes / Saves / Newest / Oldest）。如果把 select 固定为 108px，"点赞从多到少"会被截成"点赞从多"。
  - `#count` **必须**挪到 `.active` 那一行，否则搜索框只剩 132px，placeholder 会被截断。实测改完后无筛选 66px，3 个 pill 约 100–110px。
  - 吸顶阴影：用 1px sentinel 加 IO 切换 `.controls.stuck{box-shadow:0 8px 16px -12px rgba(36,30,30,.45)}`。
  - 不要用 `maximum-scale=1`（会禁止双指缩放），不要加 `select{min-height:44px}`，也不要做"下滑隐藏"（会和 #3 的回位冲突）。
- **位置**：L24、L129-137、L191、L289-303
- **工作量**：S

### 10. 排序结果误导："点赞"混入 GitHub star，"收藏"在非 X 来源下无效，默认顺序只有 X
- **问题**：
  - L402 用 `likes??stars` 排序，前 12 名里有 10 个是 GitHub star（OpenClaw ★390,818 等）。点赞榜第 1 名（♥16.9k）在这个排序里只排第 11。
  - 收藏数据只有 X 有，在 Reddit、GitHub 等来源下，按收藏排序的结果和默认顺序完全一样，而且没有任何提示。

## 保持不变的优点

- **品牌系统执行一致**：方角、mono kicker、编号方块加蓝色下划线的章节标题；深色证据区和紫色 CTA 区给长页面带来明暗节奏；倾斜 chip 在 360/390 宽下也不会互相碰撞。
- **分面计数逻辑正确**：每个分面按"其他条件 + 搜索"计数，不计自身（`filtered(ignore)`）；筛选项全是真正的 `<button>` 加 `aria-pressed`。分类柱的 lime 选中态（ink 字 11.27:1）是全页选中态最好的范本，来源栏和证据区应该向它看齐。
- **布局稳定**：16:9 `aspect-ratio` 预留了空间，加上 `loading=lazy` 和 `referrerpolicy=no-referrer`（B 站防盗链需要），图片正常加载时 CLS 为 0。360/390 宽下 zh、en 都没有横向溢出；同一行卡片等高，页脚贴底，数字列用 tabular-nums。
- **搜索快，且双语互搜**：150ms 防抖，5,053 条过滤只需 10–35ms；中英文字段一起建索引。
- **双语数据完整**：5,053 条没有一条缺英文标题或摘要；切换语言时保留筛选、排序和搜索，并同步 `html[lang]`；localStorage 读写都包了 try/catch。
- **`prefers-reduced-motion` 覆盖完整**（L221-226），新增的动效直接沿用即可；页面没有外部字体和第三方脚本，CDN 已经用 brotli 压缩（4.0 MB→1.13 MB）。
